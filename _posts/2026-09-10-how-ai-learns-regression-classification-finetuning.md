오늘은 **인공지능이 "배운다"는 게 정확히 무슨 일인지**를 세 번 직접 확인했습니다. 카페 매출을 맞히고, 손글씨를 알아보고, 남이 배운 걸 물려받는 순서로요.

결론부터 말하면 이렇습니다. **학습은 마법이 아니라 "예측하고, 틀린 만큼 숫자를 고치는" 반복입니다.** 그리고 결과를 가르는 건 화려한 모델이 아니라 **데이터**였습니다.

## 1. 왜 규칙을 직접 안 짜고 배우게 할까

개와 고양이를 구분하는 규칙을 직접 써 본다고 해봅시다.

- "귀가 뾰족하면 고양이" → **폴드귀 고양이**가 반례입니다
- "수염이 있으면 고양이" → 개도 수염이 있습니다

스팸 메일도 마찬가지입니다. '무료'와 '당첨'을 막으면 **'무 료'**, **'당.첨'** 으로 비틀어 빠져나갑니다. 예외가 예외를 부르고, 규칙은 술래잡기처럼 끝없이 늘어납니다.

그래서 방향을 뒤집습니다.

> **규칙을 사람이 다 적는 대신, 예시를 잔뜩 주고 기계가 규칙을 스스로 찾게 한다.**

이게 인공지능의 "학습"입니다. 1959년 아서 새뮤얼이 기계학습을 *"명시적으로 프로그래밍하지 않고도 컴퓨터가 배우게 하는 연구"* 라고 설명한 그 관점이죠.

참고로 용어들은 겹겹이 포개져 있습니다. 가장 넓은 원이 **인공지능**, 그 안에 데이터로 배우는 **머신러닝**, 다시 그 안에 여러 층을 쌓는 **딥러닝**이 들어앉습니다. 요즘의 생성형 AI도 대개 딥러닝 위에 서 있습니다.

## 2. 학습 = 네 칸짜리 고리

학습의 정체는 놀랄 만큼 단순한 반복입니다.

```
데이터 → 예측 → 틀린 정도(오차) 계산 → 내부 숫자(가중치) 조정 → 다시 반복
```

모델이 5를 예측했는데 정답이 7이면 오차는 +2입니다. 이 오차를 줄이는 방향으로 숫자를 아주 조금 밀어서, 다음엔 5.3, 그다음엔 5.6… 이렇게 정답에 다가갑니다.

오차를 **언덕**이라고 보면, 가장 낮은 골짜기를 향해 한 걸음씩 내려가는 셈입니다. 그래서 이름이 **경사하강(gradient descent)** 입니다.

### 이 고리가 만들어진 계보

| 연도 | 사람 | 한 일 |
|---|---|---|
| 1951 | 클로드 섀넌 | 다음 글자 맞히기 실험 — 언어는 통계적으로 예측 가능하다 |
| 1958 | 프랭크 로젠블랫 | 퍼셉트론 — "틀리면 틀린 만큼 가중치를 고친다" |
| 1986 | 러멜하트·힌턴·윌리엄스 | **역전파** — 여러 겹에서도 오차 기여도를 되짚어 준다 |

로젠블랫의 모델은 한 겹뿐이라 복잡한 패턴을 못 배웠습니다. 그 한계를 푼 것이 역전파고, **오늘날 GPT를 포함한 거의 모든 신경망이 이 방식으로 학습합니다.**

그리고 섀넌이 1951년에 사람에게 시켰던 "다음 글자 맞히기" 게임 — 오늘의 거대 언어 모델이 하는 **다음 토큰 예측**이 정확히 그 기계 버전입니다. 70여 년 전 게임이 지금까지 이어진 거죠.

### 중요한 단서 하나

학습의 결과물은 **규칙집이 아니라 파라미터에 압축된 패턴**입니다. 여기서 "외운다"와 "일반화한다"가 갈립니다.

우리가 원하는 건 새 입력에도 잘 대응하는 일반화지만, **일반화는 어디까지나 추정**입니다. 그래서 이런 일이 생깁니다.

> **모델은 자신 있게 틀릴 수 있습니다.**

## 3. 기계는 숫자만 만질 수 있다

기계는 글자도 그림도 직접 다루지 못합니다. **오직 숫자뿐**입니다. 그래서 무엇을 학습시키든 첫 단계는 늘 같습니다 — 숫자로 바꾸기.

**글**은 의미를 지닌 조각인 **토큰**으로 자른 뒤, 각 토큰을 숫자 묶음인 **벡터**로 바꿉니다. 이때 비슷한 맥락에서 쓰이는 단어일수록 비슷한 벡터가 되게 맞추는데, 이렇게 뜻을 담은 벡터를 **임베딩**이라고 부릅니다. *"이웃을 보면 그 단어의 뜻을 안다"* 는 오래된 언어학의 발상이죠.

**그림**은 픽셀 격자입니다. 손글씨 숫자 한 장은 28×28, 즉 **784개의 밝기 숫자**로 적힙니다.

### 숫자를 늘어놓는 사다리

| 차수 | 이름 | 예 |
|---|---|---|
| 0차 | 스칼라 | 매출 `7` |
| 1차 | 벡터 | `[방문객, 요일, 날씨]` |
| 2차 | 행렬 | 흑백 사진 (세로 × 가로) |
| 3차 이상 | 텐서 | 컬러 사진 (높이 × 너비 × 3) |

**텐서**는 "숫자를 몇 방향으로 늘어놓았나"를 일반화한 말입니다. 스칼라·벡터·행렬을 다 포함하고요.

### 비슷함을 재는 두 가지 방법

벡터를 좌표 위의 점으로 놓으면 "비슷함"을 두 가지로 잽니다.

- **거리** — 두 점이 얼마나 붙어 있나. 지도에서 서울-인천은 가깝고 서울-부산은 먼 것과 같습니다
- **방향** — 크기는 달라도 같은 쪽을 가리키면 "결이 같다"

그리고 핵심은 이겁니다. **점의 절대 위치가 아니라, 점들 사이의 관계가 뜻을 만듭니다.**

## 4. 신경망 한 층은 세 박자다

이름은 거창해도 한 층이 하는 일은 단출합니다.

> **곱하고(W) → 더하고(b) → 비틀기(활성화 함수)**

식으로 쓰면 `Wx + b`, 그게 전부입니다. 가중치는 "이 입력이 얼마나 중요한가"를 반영하고, 편향은 저울의 영점을 맞추듯 결과를 위아래로 밀어 줍니다.

### 왜 굳이 '비틀기'가 필요할까

여기가 재밌는 부분입니다. **직선 위에 직선을 아무리 얹어도 결국 직선**입니다. 곱하고 더하기만 층층이 쌓으면 전체가 하나의 직선으로 뭉개져서, 구불구불한 진짜 세상의 패턴은 영영 못 그립니다.

그래서 층마다 끝에 꺾임을 하나 넣습니다. 가장 사랑받는 **ReLU** 는 하는 일이 허무할 만큼 단순합니다.

> 음수가 나오면 **0으로 눌러** 버리고, 양수는 **그대로** 통과시킨다.

이 작은 꺾임 하나가 밋밋한 직선들의 합을 **곡선까지 그릴 줄 아는 모델**로 바꿔 놓습니다.

숫자로 따라가 보면, 입력 `x=[2,1]`, 가중치 `W=[0.5,-1]`, 편향 `b=0.2` 일 때 → `2×0.5 + 1×(-1) + 0.2 = 0.2` → 양수라 ReLU를 지나도 `0.2` 그대로입니다.

## 5. 파라미터 2개로 학습을 눈으로 보기

말로만 들으면 여전히 추상적이라, **가장 작은 학습**을 직접 돌렸습니다. 학습되는 숫자가 **weight 1개, bias 1개**뿐인 모델입니다.

**상황** — 작은 카페의 30일치 (방문객, 매출) 기록이 있습니다. 이 데이터는 사실 `매출 = 2 × 방문객 + 1` 이라는 숨은 규칙에 잡음을 섞어 만든 건데, **모델은 그 규칙을 모릅니다.** 0에서 출발합니다.

핵심 루프는 이렇게 생겼습니다.

```python
pred = model(x)                    # ① 예측
loss = ((pred - y) ** 2).mean()    # ② 오차 (평균제곱오차)
loss.backward()                    # ③ 기울기 계산 (역전파)
w -= lr * w.grad                   # ④ 기울기 반대 방향으로 한 걸음
b -= lr * b.grad
```

**결과:**

```
학습된 규칙:  매출 = 2.07 * 방문객 + 0.79     (숨은 정답: 2.00, 1.00)
```

아무도 알려주지 않았는데, **데이터 30개만 보고 규칙을 찾아냈습니다.** 기울기 2.07은 "방문객이 100명 늘면 매출이 약 207만원 는다", 절편 0.79는 "방문객 0명인 날에도 잡히는 기본 매출 약 80만원"으로 읽힙니다.

절편이 정답에서 더 흔들리는 이유도 설명됩니다. 절편은 방문객 0명 지점의 값인데, 그 지점이 **데이터 중심에서 멀리 떨어져 있어** 잡음에 더 민감하거든요.

### 그리고 이게 LLM과 같습니다

거대 언어 모델도 다르지 않습니다. **다른 건 오직 규모**입니다.

- 파라미터가 2개가 아니라 수십억~수천억 개
- 예측하는 것이 숫자 하나가 아니라 **다음 토큰의 확률분포**

방식은 똑같이 "예측 → 오차 → 조정"의 반복입니다. 그리고 이 작은 학습을 **웹 전체 규모로 돌린 것**이 바로 모델의 **사전학습(pretraining)** 입니다.

## 6. softmax — 확률로 답하기

카페는 "매출"이라는 연속된 숫자를 맞히는 문제였습니다. 이런 걸 **회귀**라고 합니다. 그런데 세상 많은 문제는 "어느 쪽인가"를 고르는 **분류**입니다.

분류에서 모델의 출력은 정답 하나가 아니라 **후보마다 매긴 확률**입니다. "3일 확률 88%, 8일 확률 9%, 5일 확률 2%…" 이렇게요.

여러 후보의 점수를 **모두 0~1 사이이고 합이 1인 확률**로 바꿔 주는 장치가 **softmax** 입니다.

```
로짓(raw 점수)      : [2.0, 1.0, 0.1]
① exp 적용          : [7.39, 2.72, 1.11]    ← 모두 양수로, 차이는 더 벌려서
② 합(11.2)으로 나눔 : [0.66, 0.24, 0.10]    ← 합 = 1
```

**왜 이름이 softmax일까요?** 그냥 max는 가장 큰 하나만 1, 나머지는 0으로 딱 잘라 버립니다(hard). softmax는 큰 값에 큰 확률을 주되 **나머지에도 확률을 조금씩 남겨** 부드럽게(soft) 고릅니다. 그래서 soft + max.

이게 실무에서 중요한 이유가 있습니다. **확률값 자체가 "얼마나 확신하는지"를 알려주기 때문**입니다. 0.66이면 애매하고 0.99면 강한 확신이죠. 그래서 *"확률이 낮으면 사람에게 넘긴다"* 같은 판단 기준을 세울 수 있습니다.

그리고 **언어모델이 다음 단어를 고를 때 쓰는 것과 똑같은 장치**입니다. LLM은 후보 수만 개에, 숫자 분류기는 0~9 열 개에 확률을 매길 뿐 원리는 같습니다.

연습 대상은 기계학습의 "Hello World"인 **MNIST**(손글씨 숫자 7만 장)였습니다. 그리고 여기서 오늘의 결론을 미리 만났습니다.

> 전체 데이터로 학습하면 96%대. **데이터를 10%로 줄이면 정확도가 떨어집니다.**
> 모델이 나빠져서가 아니라 **볼 예시가 줄었기 때문**입니다.

## 7. 파인튜닝 — 남이 배운 것을 물려받기

MNIST는 밑바닥부터 배워도 금방입니다. 하지만 개와 고양이를 구분하려면 귀·털·눈·질감 같은 복잡한 시각 특징이 필요하고, 이걸 처음부터 배우려면 엄청난 사진과 계산이 듭니다. 우리에겐 몇백 장뿐일 수도 있고요.

그래서 **남이 이미 배운 것을 물려받습니다.**

수백만 장으로 미리 학습된 모델(예: ResNet18 — 여기서 18은 층 수입니다)은 이미 "선·모서리·질감·형태"를 보는 눈을 갖고 있습니다. **그 눈은 그대로 두고 마지막 판단 부분만** 내 문제에 맞게 조금 더 학습시키는 것, 이게 **파인튜닝**입니다.

### 무엇이 전이되는 걸까

신경망은 층을 지날수록 점점 복잡한 것을 봅니다.

- **앞쪽 층** — 선·모서리·색 같은 **보편적** 패턴
- **뒤쪽 층** — 눈·귀·질감 같은 **구체적** 형태

개든 고양이든 자동차든 '이미지'이기만 하면 **앞쪽의 "선을 보는 눈"은 똑같이 쓸모 있습니다.** 그래서 앞쪽 층은 그대로 **얼려 두고(freeze)** 뒤쪽 판단 층부터만 새로 배웁니다. 데이터와 계산을 아끼는 거죠.

**데이터가 적을 때 사전학습 쪽이 밑바닥 학습보다 크게 앞섭니다.**

## 8. 왜 내 노트북으론 벅찰까

파인튜닝쯤 오면 노트북이 버거워집니다. 이유는 **학습되는 숫자의 개수**가 문제마다 하늘과 땅 차이이기 때문입니다.

| 오늘의 학습 | 파라미터 | 어디서 도나 |
|---|---|---|
| 카페 선형모델 | **2개** | 노트북에서 즉시 |
| MNIST 분류기 | 수만 ~ 수십만 | 노트북 CPU로 몇 분 |
| ResNet18 파인튜닝 | 약 **1,100만** | GPU 권장 (Colab 등) |
| 대형 언어모델 | 수십억 ~ **수천억** | GPU 수백~수천 대, 데이터센터 |

학습 계산의 대부분은 **방대한 행렬 곱셈**입니다. 파라미터와 데이터가 많아질수록 곱셈 횟수가 폭발합니다.

**그래서 GPU를 씁니다.** CPU는 복잡한 일을 순서대로 빠르게 처리하는 코어가 소수인 반면, GPU는 단순한 계산을 동시에 처리하는 코어를 **수천 개** 갖고 있습니다. 행렬 곱셈 안의 수많은 곱셈은 서로 독립이라 순서 없이 한꺼번에 계산할 수 있어서, GPU에 딱 맞습니다.

규모 감각을 하나 붙이면 — **LLM의 수천억 개 파라미터를 1초에 하나씩 세기만 해도 수천 년이 걸립니다.** 학습은 이 숫자 전부를 수없이 조정하는 일이니, 왜 데이터센터가 필요한지 짐작이 갑니다. LLM을 처음부터 학습하려면 고성능 GPU 수천 대를 수 주간 돌리고 수백만~수억 달러가 듭니다.

그래서 **현실의 실무는 대부분 직접 훈련하지 않습니다.** 이미 학습된 모델을 파인튜닝하거나 API로 부릅니다.

### Colab CLI — 터미널에서 GPU 빌리기

GPU가 없는 노트북에서는 구글 코랩을 씁니다. 그런데 2026년 6월, 구글이 터미널용 도구를 하나 더 얹었습니다. **Colab CLI**(공식 패키지 `google-colab-cli`)입니다.

```bash
pip install google-colab-cli
colab run --gpu T4 train.py     # GPU VM 띄움 → 실행 → 자동 반납
```

무료 요금제에서는 보통 T4가 주어지고, A100·H100이나 TPU는 유료입니다.

여기서 오늘 실습 방식과 딱 맞물리는 점이 있습니다. **Colab CLI는 AI 에이전트가 직접 쓰도록 설계됐습니다.** Claude Code 같은 코딩 에이전트가 이 명령을 대신 실행할 수 있어서, "에이전트에게 시킨다"가 말뿐이 아니라 **실제 GPU에서 코드를 돌리고 정확도를 받아오는 데까지** 이어집니다.

## 9. 결국 데이터가 전부다

오늘 학습을 세 번 봤습니다.

| | 무엇을 예측하나 | 방법 |
|---|---|---|
| **회귀** (카페 매출) | 연속된 숫자 | 예측 → 오차 → 조정으로 직선을 찾음 |
| **분류** (MNIST) | 어느 범주인지 | softmax로 확률을 매겨 고름 |
| **파인튜닝** (개/고양이) | 어느 범주인지 | 사전학습된 특징을 물려받아 적은 데이터로 맞춤 |

셋을 관통하는 한 문장은 이것입니다.

> **모델 구조보다 데이터가 결과를 가른다.**

데이터를 10%로 줄이면 정확도가 떨어졌고, 사전학습된 특징을 물려받으면 적은 데이터로도 잘 됐습니다. 그래서 **AI를 다루는 사람의 진짜 일은 "좋은 모델 고르기"보다 좋은 데이터를 모으고 검증하는 것**에 가깝습니다.

앞으로 직접 학습을 돌릴 일은 많지 않을 겁니다. 하지만 오늘 원리를 봤기 때문에, 코딩 에이전트에게 **무엇을 시킬지**(무슨 데이터로, 어떤 학습을), 그리고 **나온 결과의 무엇을 의심할지**(데이터가 충분한가, 정확도가 왜 이런가) 판단할 수 있습니다.

오늘은 크게 두 갈래를 배웠다. 하나는 **AI에게 일을 맡길 작업대를 어떻게 차리는가**, 다른 하나는 **그 결과물을 GitHub으로 어떻게 협업·배포하는가**다. 둘은 이어지는 흐름이라 한 번에 정리한다.

## 1. AI 작업대, 뭘 깔아야 하나 (초보 정리)

오늘 배운 걸 한 줄로 말하면: **AI한테 일 시키려면 일할 책상부터 있어야 한다**는 거였다. Claude Code한테 "이거 만들어줘" 해도, 내 컴퓨터에 그걸 실행할 자리가 없으면 그냥 파일만 생기고 끝이다.

그 "책상"에 필요한 게 다섯 개였다.

- **Claude Code** — AI한테 실제로 일 시키는 도구. Desktop(마우스로 보는 화면)이랑 터미널(글자 화면) 두 가지가 있는데 사실 같은 놈이다.
- **Node.js / npm** — 자바스크립트 코드를 돌려주는 엔진이랑, 필요한 부품 다운받는 창고.
- **uv** — 파이썬 버전이라고 생각하면 됨. 나중에 파이썬 도구 쓸 때 필요해서 미리 깔아둠.
- **Git** — AI가 파일 막 고쳐도 이전으로 되돌릴 수 있게 해주는 안전장치. 이거 있으면 마음 놓고 실험 가능.
- **터미널** — 명령어 치고 결과(에러 포함) 확인하는 창.

오늘의 한 줄: 개발 환경은 결국 AI가 일한 결과를 바로 보고 다시 시킬 수 있게 해주는 작업대다. 처음엔 도구 이름이 낯설어도, 그냥 "이 다섯 개가 세트로 필요하구나" 정도만 알고 넘어가면 될 것 같다.

## 2. GitHub 협업 흐름: Fork → Clone → PR

여러 사람이 하나의 "마스터(Master)" 저장소를 중심으로 작업할 때 쓰는 표준 흐름이다.

1. **Fork**: 마스터 GitHub 저장소를 내 계정으로 복제 (우측 상단 Fork 클릭)
2. **Clone**: 포크한 저장소를 내 PC로 가져오기 — 이 단계부터 Claude Code에 자연어로 시킬 수 있다 (`"이 레포지토리를 현재 작업 폴더에 클론해와"`)
3. **수정**: 예를 들어 README.md를 가상 인물 자기소개로 채우고 이미지까지 넣는 작업도 Claude Code에 자연어로 지시 가능
4. **Commit & Push**: 변경 내용을 로컬 Git에 기록(commit)하고 내 GitHub 원격 저장소에 반영(push) — 이것도 "변경된 모든 내용을 커밋하고 푸쉬해줘" 한 마디로 처리
5. **Pull Request(PR)**: 내 GitHub → 마스터 GitHub로 병합 요청. 제목과 변경 요약(description)을 작성해 리뷰어가 맥락을 알 수 있게 한다
6. **리뷰 루프**:
   - 승인되면 매니저가 최종 merge
   - 수정 요청이 있으면 PR의 Conversation 탭 댓글로 온다 → 로컬에서 Claude Code로 반영 → 다시 commit & push하면 **내 저장소와 마스터 PR에 동시 반영**됨 (별도 재제출 불필요)
   - 반영 후 Conversation 탭에 완료 코멘트를 남기면 매니저가 재검토

**포인트**: 한 번 PR을 열어두면, 이후 수정은 그냥 로컬에서 고치고 commit/push만 하면 자동으로 같은 PR에 쌓인다. 즉 "마스터에게 반영 요청" 절차가 최초 PR 생성 한 번으로 끝나고, 그 다음부턴 코드만 갱신하면 된다.

## 3. 실습 데모: GitHub로 블로그 만들기

위 Fork → Clone → PR 흐름을 실제로 GitHub 기반 블로그(예: GitHub Pages) 제작에 적용해보는 실습 영상을 함께 진행했다. 개념(작업대·Git 협업)을 바로 손으로 옮겨보는 단계로, "이론 → 실습"이 한 세트로 묶인 하루였다.

## 오늘의 한 줄 정리

> AI에게 일을 시키려면 실행할 작업대(Claude Code + Node.js/npm + uv + Git + 터미널)가 먼저 있어야 하고, 그 결과물을 여러 사람과 나누려면 Fork-Clone-PR이라는 GitHub의 표준 협업 루프를 타야 한다.

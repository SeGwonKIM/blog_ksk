Claude Code를 쓰다 보면 대화 중 입력하는 슬래시 명령어, 프로젝트에 설정된 커스텀 스킬, 터미널에서 바로 치는 CLI 명령이 뒤섞여 헷갈리기 쉽다. 한 번 정리해두면 두고 쓰기 좋을 것 같아 카테고리별로 묶어봤다.

## 1. 기본 슬래시 명령어 (대화 중 입력)

| 명령어 | 기능 |
|---|---|
| `/help` | 도움말 및 사용 가능한 명령어 목록 |
| `/clear` | 대화 컨텍스트 초기화 |
| `/compact` | 대화 내용을 요약해서 컨텍스트 절약 |
| `/config` | 설정 변경 (테마, 모델 등) |
| `/cost` | 현재 세션 토큰/비용 확인 |
| `/model` | 사용할 모델 전환 |
| `/mcp` | 연결된 MCP 서버 관리 |
| `/memory` | 메모리(기억) 파일 편집 |
| `/permissions` | 도구 실행 권한 설정 |
| `/agents` | 서브에이전트 관리 |
| `/hooks` | 훅(자동 실행 스크립트) 설정 |
| `/init` | 프로젝트에 CLAUDE.md 초기 생성 |
| `/review` | PR/변경사항 코드 리뷰 |
| `/bug` | 버그 리포트 제출 |
| `/status` | 계정/세션 상태 확인 |
| `/export` | 대화 내보내기 |
| `/add-dir` | 작업 디렉터리 추가 |
| `/vim` | vim 키바인딩 모드 전환 |
| `/exit` | 세션 종료 |

## 2. 프로젝트에 설정된 스킬(커스텀 명령어)

| 명령어 | 기능 |
|---|---|
| `/loop` | 특정 작업을 주기적으로 반복 실행 |
| `/schedule` | cron 기반 예약 작업 생성 |
| `/code-review` | 현재 diff/PR 코드 리뷰 (버그·중복·효율성 체크) |
| `/simplify` | 코드 단순화·리팩터링 적용 |
| `/security-review` | 보안 취약점 검토 |
| `/design` | 시각적 디자인 캔버스(목업 등) 생성 |
| `/fewer-permission-prompts` | 반복되는 권한 승인 요청 줄이기 |

## 3. 터미널 CLI 명령/플래그 (`claude ...`)

| 명령 | 기능 |
|---|---|
| `claude` | 대화형 세션 시작 |
| `claude "질문"` | 프롬프트 즉시 전달 후 실행 |
| `claude --print` | 결과만 출력하고 종료 (스크립트용) |
| `claude --continue` / `-c` | 가장 최근 세션 이어가기 |
| `claude --resume` | 이전 세션 목록에서 선택해 재개 |
| `claude --model <name>` | 사용할 모델 지정 |
| `claude mcp` | MCP 서버 등록/관리 |
| `claude plugin` | 플러그인 설치/관리 |

## 4. 유용한 단축키

- `!` + 명령어 — 셸 명령을 세션에서 직접 실행 (출력이 대화에 포함됨)
- `Shift+Tab` — 권한 모드 전환 (예: auto-accept)
- `Esc` — 진행 중인 작업 중단

## 느낀 점

명령어를 종류별(대화형 슬래시 / 프로젝트 스킬 / 터미널 CLI)로 나눠보니, 왜 같은 `/` 로 시작해도 어디서는 되고 어디서는 안 되는지가 이해됐다. 특히 스킬은 프로젝트마다 다르게 설정될 수 있다는 점을 기억해두려고 한다.
